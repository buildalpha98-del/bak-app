Configurable Kanban Columns

Your DB currently has a fixed enum (todo, in_progress, done). How should we handle admin-configurable columns?

A

Flexible Columns Table (Recommended)

Create a task_columns table with id, name, position, is_final, colour. Change tasks.status from enum to a foreign key. Admins can add real columns like "Blocked", "Review", "Waiting on Client". The "Done" column is permanent (is_final = true).

Pros

  • Truly configurable — unlimited custom columns
  • Clean relational model
  • Supports colour-coded columns

Cons

  • Migration needed to drop enum + add FK
  • Slightly more complex queries
B

Keep Fixed 3-Status Enum

Keep the existing todo | in_progress | done enum. Admin can only rename the display labels in the UI — not add real new statuses. Simplest approach but limited.

Pros

  • No migration needed
  • Simplest implementation

Cons

  • Can't add "Blocked", "Review", etc.
  • Doesn't deliver true configurability
C

Soft Enum with Varchar

Change tasks.status from enum to varchar. Store valid statuses in a task_columns config table. No FK constraint — validation happens at the app layer.

Pros

  • Flexible without FK overhead
  • Easier migration (just alter column type)

Cons

  • No DB-level integrity (orphan statuses possible)
  • App-layer validation required
